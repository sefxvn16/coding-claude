# Specs: linking, committing, clarifications, criterion ids

Read at step 2 (brief) and 2b (spec commit), and for a small task that changes behavior a spec describes. The core rules (source of truth, order of change, marker check) are in SKILL.md.

- Linking: when `design/features.json` exists, a spec's `Feature id` links it to that feature; `features.json` keeps the feature list, the spec keeps the behavior rules; never copy one into the other. No `specs/` yet: the first complex task on a feature creates its spec; do not backfill specs for features the task does not touch.
- Writing: the spec agent returns the brief plus the full text of each new or changed spec (template `templates/spec.md`). The M1 dossier shows the spec diff. After M1, YOU write the owner's answers into the spec and commit the approved spec on `cs/<task-id>` as its own commit before design or code; record its hash in `PLAN.md` and the handoffs. A later owner-approved spec fix (e.g. after a builder reports the spec wrong) is another spec-only commit, recorded the same way.
- Modules: the spec files go into `scope.json` `files`; this also lets the hook allow builder edits there, so only the handoff rule and the reviewer stop a builder from editing `specs/**`.
- Clarification: every ambiguity is marked inline as `[NEEDS CLARIFICATION: <question>]` in the spec and the brief and listed under Open questions; the spec agent never guesses an answer. Owner answers go into the spec's Decisions with the date and replace the markers; a question the owner chooses to leave open moves to the spec's Deferred section without the marker. A committed spec never holds a marker.
- Criteria: every criterion is Given / When / Then with concrete values, and edge cases are criteria of their own; the spec agent sets `Test-first: yes` for business rules and calculations. Check this before M1.
- Criterion ids: `<feature>/A<n>` (e.g. `discount-code/A3`), stable for the life of the spec; a removed id is never reused. A criterion checked by an automated test has its id in that test's name or title, so `grep -rnw --exclude-dir=node_modules --exclude-dir=.git "discount-code/A3" .` finds it (`-w`: A3 does not match A30). Given / When / Then lives only in the spec; the brief lists ids and checks. `Test-first: yes` means the builder commits that test in its own commit before the code commit and reports its failing output.
