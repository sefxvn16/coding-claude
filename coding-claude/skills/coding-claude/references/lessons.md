# Lessons (`LESSONS.md`)

Project memory across tasks: short rules learned from real failures, in `LESSONS.md` at the project root, committed with the code. You write them, the reviewer checks them, the lessons script prunes them. Lessons are advisory: they add care to a handoff, never skip or loosen a check, and lose to the spec, `.studio/project.json` and CLAUDE.md when they disagree (then delete the lesson).

- When to write: on one deliverable, a verify FAIL that needed 2 or more fix rounds, or a reviewer HIGH finding that was fixed. No evidence, no lesson: never from opinion or a guess.
- Format, one line each: `- L<n> | <rule: imperative, with the consequence, max 200 characters, no " | "> | when: <situation> | files: <globs of the files involved, no wider than their module; only *, ** and ?> | evidence: <task-id> <report path> (<failing hash>) | added: YYYY-MM-DD`. The fix commit is the commit that adds the line; never put its own hash in the line. Take the id from `check` ("next id"; ids are never reused). Evidence names only reports the reviewer gets (`05-verify-<n>.md`, `06-review-<round>.md`, builder results); they live in gitignored `work/`, so they can be checked only on this machine while the task runs. A new file starts from `templates/lessons.md`.
- Commit: add the line in the same commit as the fix, before the verify that follows it, and run `check` first; give the reviewer the new ids and the `check` output. A line added in a round-1 fix is judged in round 2.
- DROP: remove the line in a commit that changes only `LESSONS.md`. That commit keeps the verify and review results of its parent (the dossier names both hashes), needs no new verify, and its review is only step 4b on that diff, outside the round cap.
- Recurrence: the same failure again although a matching lesson was in the handoff means the lesson is wrong or too narrow: rewrite it with the new evidence or delete it, through the same review.
- Prune: put the `REMOVED ...` lines printed by `prune` in the body of the `lessons: prune` commit message; the reviewer reads them there. `prune` refuses to write while `check` reports problems. Parallel tasks merge `LESSONS.md` with `merge=union` (init sets it in `.gitattributes`): a merge can bring back a pruned line (the next prune removes it again) or leave two lines with the same id (renumber the newer one with the next id from `check`, in its own commit).
- Never write a lesson that skips a step, loosens a check, or changes config. A check that could be automated (a forbidden pattern, a required import) goes into the next dossier as a proposed `rules` entry for `.studio/project.json`; the owner decides it there.
- Cap: 20 lines. `prune` removes lessons whose files match no tracked file, lessons older than 180 days, and the oldest over the cap.
